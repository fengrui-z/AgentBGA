# 方舟动物园已完成对局统计流程

本流程用于所有已完成的 `ark_nova` 对局。它只固化可由状态、事件和调用记录重建的客观统计；Agent 行为评价和 Harness 改进建议仍由人工审计完成，不写入自动结论。

## 触发与产物

当规则引擎把对局状态写为 `finished` 后，Runner 在发布 `match_finished` 事件前生成 `agentbga.ark-nova.match-report.v6` 报告，并把它保存到 SQLite 的 `match_reports` 表。Web 快照在赢家区下方显示：

1. 墙钟耗时、总回合、总决策和休息次数；
2. 每回合实时轨道分数趋势，休息触发点用竖线标记；
3. 每个座位的模型调用成功率、回退率和缺失耗时数量；
4. 固定统计表，列为最终排名后的玩家，行为项按行动、资源、卡牌、协会、地图、升级和图标分组。

已完成对局是不可变数据；Web 服务重启后，`?match=MATCH_ID` 可以从 SQLite 重建只读快照和报告。仍在进行的对局不能这样伪恢复，因为对应 Runner 已经不存在。

也可以离线重建或读取报告：

```bash
./agentbga match report MATCH_ID --json
```

同一最终状态和同一事件流应产生相同统计值；`generated_at` 除外。报告版本升级时，旧版本缓存不会被继续使用，而会按当前方法重新生成。

## 权威数据源与顺序

1. `matches`：创建时间、结束时间、seed、最终 state version；
2. 最终状态：最终轨道、地图建筑、公开图标、行动牌升级、事务员、终局牌结算；
3. `events`：行动次数、资源流、卡牌流、协会任务、休息触发与实时轨道变化；
4. `match_players`：座位、玩家名、Backend、模型和首轮顺位；
5. `model_calls`：成功/回退、错误类别和已记录的调用耗时；
6. `.agentbga/runs/_traces`：只在历史失败调用没有持久化耗时时，按同一 match、seat 的调用顺序补回进程耗时，并保留 trace 输入 state version 与 `model_calls` 提交 version 供审计；
7. 游戏 `rankings()`：正式最终分数、排名、终局牌与地图结算。

统计器不得从 Web 文案、Agent 自述、trace 自然语言或卡牌美术推断数值。

## 计算步骤

1. 验证游戏为 `ark_nova` 且状态为 `finished`。
2. 用创建事件中的原始 config 重新建立初始状态，记录第 0 回合的轨道值。
3. 按事件 `seq` 单调扫描，更新玩家轨道与计数器；每个 `turn_finished` 采样一次实时轨道分数。
4. 对 `break_triggered` 计数并记录触发座位；收入期内的基础收入和重复收入单独累计。
5. 用最终状态覆盖所有最终存量类数据，例如地图覆盖、剩余空格、建筑、升级牌和图标。
6. 用最终 `rankings()` 写入正式分数和排名；把终局采样追加到趋势序列。
7. 聚合 `model_calls`。思考时间为所有有耗时字段的调用之和；缺失耗时必须单列，不能默认为零。
8. 保存带 schema version 和 state version 的报告，并随赢家快照显示。

## 指标口径

- `游戏耗时`：`matches.updated_at - matches.created_at`，包含模型等待、重试和 Web 暂停造成的墙钟时间。
- `思考时间`：每次决策的进程耗时之和。旧对局若缺少失败调用耗时，优先按 match/seat/version 从 turn trace 补回；仍缺失的调用必须单列，不能默认为零。
- `回合数`：完成普通行动轮的总数；多阶段选择会增加决策数但不一定增加回合数。
- `已触发的休息次数`：`break_triggered` 的数量；玩家列只统计该座位触发的次数。
- `最终成绩`：终局牌和地图奖励结算后，魅力加保护轨道印刷分。
- `终局得分`：从最后一个普通行动结束到全部终局效果结算完毕，最终成绩增加的轨道分；包括终局牌、赞助商终局效果和地图终局奖励造成的变化。
- `实时轨道分数`：魅力加保护轨道印刷分，在每回合结束时采样。它用于趋势；终局阶段新增的轨道分作为独立的 `终局得分` 保存。
- `获得金钱`：基础收入、正向金钱变化、金钱图标奖励及互动转移；临时毒液预留/返还不计。
- `由收入获得的金钱`：休息处理期间的基础收入与可重复收入效果。
- `花费在动物的金钱`：动物费用，不含声望范围附加费。
- `花费在饲养区的金钱`：付费建造且最终类型是围栏的建筑；商亭、休憩亭与免费建筑不计入。
- `花费在声望范围的金钱`：从超出免费范围的展示位拿牌或打牌所付的 folder surcharge。
- `卡牌流`：牌库抽牌、展示区拿牌、精选和弃牌分别按对应事件累计；展示区奖励与 WAZA 拿牌属于展示区拿牌。
- `协会任务`：按 `association_task_performed.task_id` 分类；捐赠使用独立事件，因为它是同一次协会行动中的附加任务。
- `建筑、赞助商和图标`：使用最终状态，避免重复触发事件造成双计数，也避免独特建筑型赞助商的分阶段事件漏计。
- `行动牌升级`：使用最终状态；总数和五种行动牌分别显示。

## 完整性与异常标记

报告展示但不自动解释以下质量风险：

- `fallback_rate` 大于零：部分选择并非目标模型产生；
- `latency_missing_calls` 大于零：思考时间只是下界；
- quota、context-length、timeout 等错误按类别汇总；
- 状态不是 `finished` 时拒绝生成报告；
- 报告 state version 与最终状态不一致时拒绝复用缓存。

正式 Agent 对战比较应优先使用 `fallback=fail`，或者把存在回退的对局标成无效样本。自动报告只陈述事实，不把回退后的随机行为归因于模型策略。

## 固定验收

- 报告表包含请求的全部字段，玩家列按最终排名排序；
- 趋势包含第 0 回合、每个完成回合和一个终局采样；
- 趋势的休息计数与表格总休息次数一致；
- 两个玩家的回合数之和等于对局总回合数；
- 最终地图覆盖、建筑、升级和图标与最终 Web 投影一致；
- CLI 报告、SQLite 缓存和赢家 Web 显示使用同一份 JSON 投影。
