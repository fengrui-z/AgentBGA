# 十款游戏的人类操作体验检查

检查日期：2026-10-16。修改分支：`codex/human-play-usability`。

通过 Computer Use 在本地 Web 创建并操作十场对局：Agent 1 为 Codex Harness、ChatGPT 订阅、`gpt-6-astra`，推理强度保持页面默认的 `max`；Agent 2 为人类，由浏览器操作。七大奇迹最低需要三人，因此另加一个 random 玩家。这是开局和代表性操作检查，未打完整局，也不是完整规则验收。

## Splendor 修改

- 银行、贵族、三阶市场集中在同一牌桌。银行直接选宝石；市场牌直接购买或预留；每阶牌堆提供盲抽预留。
- 卡牌显示分数、永久折扣、原价、计入自身资源后的差额。贵族显示当前折扣 / 要求。
- 固定在视口底部的行动预览提供清空和明确确认。选择不再自动提交；支付方式来自引擎返回的合法行动，默认少用黄金，可切换其他合法方案。
- 拿取或预留超过十颗时显示退回选择，继续使用原有合法行动匹配逻辑，允许退回刚拿取的宝石或黄金。
- 玩家摘要直接显示分数 / 15、宝石 / 10 和永久折扣。已购牌详情、预留详情和完整模型日志可以展开。
- 用响应式网格替代市场的固定最小宽度；Splendor 的细节样式独立于其他游戏。

实测旧版 640×900 的人类回合页面约 2346px 高；新版同尺寸无预留牌时约 1103px，减少约 53%，没有页面横向溢出。此数值包含不同回合内容，只用于说明减少重复区块后的量级变化。

## 其余九款与共用界面修改

- 共用：人类座位摘要优先；桌面双栏；日志按需展开；行动统一先预览、清空或确认，再提交原始合法行动 ID。支付方案下拉框切换会同步预览；旋转、地形颜色、来源颜色、骰子等中间选择变化会清空旧预览。
- 日志栏：Agent 输出与 Action 记录各自提供收起/展开按钮，保留标题与行动数量；两个开关互不影响，收起后日志仍继续接收。全部收起仅保留标题行，重新打开总日志面板也保留各自的折叠状态；两个区块都展开时保留可用的记录高度，避免长模型输出挤压行动记录。
- 卡卡颂：共享地图与当前地块/旋转控件并排，保持缩放、区域检查和键盘随从落点；窄屏自动堆叠。
- 展翅：起始鸟牌的保留复选框与完整费用、栖息地、蛋容量、能力信息合并，去掉准备阶段重复手牌和空白栖息地；当前决策优先显示。保留引擎逐步弃食物的协议。
- 自然和弦：默认自己的景观；摘要里的小棋盘可展开；待放地形移到棋盘上方；个人景观与动物目标并排，市场采用紧凑网格。
- 花砖：点实际来源的颜色，再点个人图案线；每行预览放入、溢出、起始标记和新增地板罚分。完整玩家棋盘仍可展开。
- 方舟：默认人类动物园；动物园/公共牌与轨道/协会三个工作区按当前决策选择；全轨道可展开；修复官方赞助商推进休息动作的 `undefined` 文案，并让未由专用组件承接的动作仍有备用入口。
- 伯明翰：按阶段分组的方案选择紧邻地图，保留地图建造、运输目标与专注模式；确认栏显示当前选择；不再展示原始 action ID。
- 勃艮第：点骰子过滤，再点仓库、黑市或个人仓储的板块；可直接点领地高亮格，预览骰子、工人和银币费用；即时奖励、货物、结束回合仍使用原有合法方案。
- 香料：市场卡直接获取、订单直接完成、个人商人直接打出或休息；复杂交易/弃置组合使用同卡方案选择；升级逐步解释输入与输出；已用牌和对手手牌仍可展开。
- 七大奇迹：仅一份可操作手牌，每张卡集成建造、奇迹、出售及付款方案；邻城生产资源放到手牌上方；完整城市详情保留。

## 电脑宽屏补充检查

此前的桌面检查未覆盖 1920px 以上。补查发现伯明翰地图随宽度等比例增高，展翅与方舟仍将适合并排的信息纵向堆叠，因此增加了 1600px 以上的专用布局：

- 伯明翰将资源市场、行动选择移至地图旁；地图默认尺寸受屏幕高度约束，保留缩放和专注模式。同一暂停局面在 1920×1080 下的页面高度从 1962px 减为 1147px。
- 展翅将栖息地与鸟食器、手牌、公开鸟牌并排；当前两张手牌的局面在 1920×1080 下完整展示在一屏内。起始选牌仍使用全宽卡牌区。
- 方舟将手牌、终局目标与地图、资源信息并排；资源详情分两列，地图保持实际几何尺寸，避免空白区域被拉宽。
- 超宽屏牌桌最大宽度为 2200px（Splendor 为 1800px）；确认栏最大宽度为 980px 并居中，缩短选择与确认之间的鼠标移动距离。

通过 Computer Use 逐一检查全部十款游戏在实际 CSS 视口 1440×900、1600×900、1920×1080、2560×1440、2560×1080 下的布局，共 50 个页面/尺寸组合，无页面横向溢出。额外检查 Splendor 预留预览/清空和确认栏可见性、伯明翰地图专注模式及 100%→114%→100% 缩放。此轮未提交额外游戏行动。

宽屏仍保留所有信息，复杂局面并非都能一屏展示：1920×1080 的当前快照中，自然和弦约 1253px、方舟约 1304px、七大奇迹约 1536px 高。中后期卡牌增加后的布局仍需继续覆盖。

## 验证与边界

- 浏览器完成拿宝石、清空重选、确认提交、公开牌预留、获得黄金、购买预留牌；购买后资源扣除、预留数量归零并增加永久折扣。
- 浏览器检查多种支付方案的切换，以及 390px、640px、1280px 宽度下的布局。
- 5 项 Splendor 选择测试通过，覆盖三色/同色取宝石、缺货、超限退回、预留合并及合法行动可达性。
- 22 项渲染与共用控件测试、5 项 Splendor 选择测试、TypeScript、ESLint 和静态构建通过。
- 完整 Python 回归 575 项通过，1 项按配置跳过。首次沙箱运行有 12 项回环 HTTP 监听权限错误，放开本地测试端口后重跑通过。
- 超限退回与贵族选择没有在这次真实对局中自然推进到对应阶段；不能据此声称所有中后期交互都已实测。
- 已修改全部十款的 Web 界面；浏览器验证覆盖代表性路径，未完成十款游戏的完整对局与全部中后期分支验收。

## 另需跟进的运行问题

多个 Codex 日志出现模型列表刷新超时，以及 `inspect_rules` / `inspect_card` 在当前观察中不可用的错误；已观察到的回合仍能提交合法行动，不能简单归因于订阅认证失败。自然和弦等多步骤回合会多次启动思考过程，等待感较强，建议单独分析每步进程耗时与行动耗时。

同时打开多场实时对局时，新增标签页曾出现加载超时，关闭部分实时标签页后恢复。现象与同源长连接占用有关的可能性需要进一步验证；本次没有完成连接层诊断。

浏览器还记录到 vinext 的 `RSC prefetch setup error`；实际页面加载、手动操作及状态更新可用。本次没有修改框架预取逻辑，该控制台错误仍需单独排查。
